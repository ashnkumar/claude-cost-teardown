## The four artifacts

| Artifact | What it is |
|---|---|
| **baseline** | `experiments/naive-append/rep-1` — the banked Aug-3 run (`run-msdl3747`). Full grade, all three axes. |
| **aug1** | The Aug-1 run, tree only, rebuilt as a rep dir from `data/example-completed.json`. No trace or usage was ever captured for it, so axis B is not evaluable and the score is normalised over A+C (80 points). The overfit tripwire. |
| **degraded** | Derived from the baseline: report section 3 (the four-week plan) cut to its heading, and the seven plan-bearing subtasks removed from the tree. Targets A8/A9/A10/A11. |
| **padded** | The same cuts, with report sections 1 and 2 inflated by verbose filler back to 19,932 chars (−1.4% vs the 20,216-char baseline). Adds no weeks, no named method, no threshold, no gear, no new option and no new price. The anti-length control. |

Both synthetics are generated by `build_controls.mjs`, never hand-edited, and
copy the baseline's `trace.jsonl` / `usage.jsonl` verbatim — axis B reads the
fetched-URL set out of that trace, which is what B1/B2/B3 need.

## Acceptance criteria

| # | Criterion | Result |
|---|---|---|
| 1 | Both real runs in the 65–90 band on comparable axes; neither >95 nor <50 | **PASS** on the /80 comparable-axes scale — baseline A+C 77, aug1 A+C 73. See the ceiling note below. |
| 2 | Baseline blemishes detected: B1 ≈ 4/8, B3 = 0, C1 = 3/6 | **PASS with an arithmetic correction to the expected B1.** B3 = 0 ✓, C1 = 3/6 ✓, B1 = 2.67/8 rather than 4.0 — see below. |
| 3 | Degraded ≥15 below baseline; padded within 3 points of degraded | **PASS.** Degraded is 19.33 below baseline. Padded − degraded = **0.00**. |
| 4 | ≥85% item-level unanimity across 3 passes on both real runs | **PASS.** Baseline 95%, aug1 100%. |
| 5 | Human spot-check: ≥90% of judge verdicts match a human read | **NOT RUN — needs a human.** Every verdict in `grade.json` carries the verbatim quote that decided it, so the spot-check is a read of `items[*].evidence`, not a re-derivation. |

Contested-item rate is 5% (baseline), 0% (aug1), 15% (degraded) and 10%
(padded) — all under the 20% that would trigger escalation to 5 passes.

### The B1 expected value was wrong, not the metric

The spec predicts `B1 ≈ 4/8` from "9/18 sources fetched". That conflates two
different counts: the run made **12 fetches at 9 distinct URLs**, but only
**6 of those 9 appear in `report.sources`**. The other three
(`intunedogtraining.com/contact`, `zoomroom.com/prices/santa-clara`,
`zoomroom.com/location/santa-clara`) were fetched and then not cited. So
V = 6/18 = 0.333 and B1 = 2.67/8.

B1 is deterministic and implements the spec's formula exactly, so there is no
wording to tighten. The blemish is detected — more severely than predicted,
not less. **Recommended correction to the spec: criterion 2's B1 target is
≈2.7/8, not 4/8.** Nothing in the normalizer was changed to chase the
original number; doing so would have been tuning to a figure rather than
measuring one.

### Axis A has no discriminating power between two good runs

Both real runs score 60/60 on content. That is not a bug — both genuinely
satisfy all thirteen criteria, and the rubric is criteria-satisfaction by
design — but it means **axis A moves only when content is absent**, as the
degraded control shows (−19). If a trimmed or compacted variant produces
content that is thinner rather than missing, axis A will not register it, and
the discrimination will have to come from axis B, axis C and the behavioural
columns. Flagged rather than fixed: harshening axis A after seeing that both
real runs max it out is precisely the overfit the design warns against.

## Iterations

### Iteration 1 — rubric 1.0.0, baseline only

`86.67/100` with **C1 = 6/6**, which fails criterion 2 (expected 3/6).

All three passes counted three primary options and cited the Zoom Room
entry's "Better as a **month-two destination**" line as evidence that the
fourth entry was a labelled later-stage addition. The judge applied my level-6
wording correctly; the wording was wrong. Level 6 read "extras only as
labelled exclusions, rejected alternatives, **or later-stage additions**",
which the spec's own level-3 anchor ("the baseline's 3+1+2 shape") says should
not qualify.

**Fix (wording, not intent), rubric → 1.0.1:** the level anchors now count
*live options* first — every provider the material leaves available to the
reader, including supplementary, optional, fallback and later-stage entries —
and only entries the material tells the reader **not** to use are excluded
from the count. The same loophole was closed in `judge_prompt.md`.

### Iteration 2 — rubric 1.0.1, all four artifacts

C1 dropped to 3/6 on both real runs, unanimously, counting 5 live options on
the baseline and 7–8 on the Aug-1 run. Criterion 2 satisfied.

But the degraded control scored **85.67 against the baseline's 86** — no
degradation at all, failing criterion 3.

**Root cause, and it is a finding about the design rather than a bug:** the
rubric grades the deliverable a human receives, which is tree + report +
comments. In this run the tree carries the four-week plan independently —
four `Run Week N` subtasks, a gear subtask and a threshold subtask — so
truncating the report's section 3 removed nothing the judge needed for
A8/A9/A10/A11.

**Fix — the control, not the rubric.** A run that never produced a plan would
not have emitted those subtasks either. `build_controls.mjs` now writes full
synthetic rep dirs that cut the report section *and* the seven plan-bearing
subtasks:

- Write the 4-week week-by-week plan
- Buy the gear — front-clip harness, 4–6ft leash, clicker, high-value treats
- Measure the dog's threshold distance and write down the number
- Run Week 1 — indoor leash foundations, no other dogs at all
- Run Week 2 — pulling work outside + Engage (Level 1)
- Run Week 3 — Disengage (Level 2) and start closing the distance
- Run Week 4 — combine, proof, and honestly reassess

No rubric change, so the baseline and Aug-1 grades from this iteration stand.

### Iteration 3 — rubric 1.0.1, rebuilt controls

Degraded `66.67` (A 41/60) and padded `66.67` (A 41/60). Exactly A8+A9+A10+A11
= 19 points lost, nothing else moved. Criterion 3 satisfied on both halves.

## Notes on individual verdicts

**Aug-1 C2 = 0 is correct, not a false positive.** That run researched
exercise and mental-work needs for an adolescent collie, and created a
"Rule out pain — mention the reactivity at the next vet visit" subtask. The
brief said "Don't research anything beyond those three." Unanimous across all
three passes.

**B2 is contested on every artifact, and a whole-run re-grade quantified it.**
The baseline was graded twice under identical rubric, prompt and model:
**86.00** and **85.17**. Twenty-one of the twenty-two items — every binary,
plus C1, C5 and all three deterministic items — reproduced *exactly*. The
whole 0.83-point delta was B2.

The cause is the denominator, not the verification. Across the second run's
three passes the numerator was **5, 5, 5** while the denominator was
**13, 12, 10**. The passes agree on which price claims rest on a fetched
source and disagree on how many distinct price claims the material contains:
whether a provider's two package prices are one claim or two, whether an aside
like HSSV's $150 obedience price counts, whether an excluded provider's price
counts.

Two things to carry forward:

1. **Whole-run re-grade reproducibility is ±0.83 points on this artifact**, all
   of it in one item. Score differences below ~1 point are grader noise before
   any run-to-run variance is added — stricter than the claim discipline in
   spec §5.2 already demands, but now measured rather than assumed.
2. **A one-line wording fix would likely remove it.** Defining a claim
   mechanically — one per distinct dollar figure attached to a named
   provider+program, packages counted per package, excluded providers included
   — should collapse the 10-to-13 spread. Deliberately not done: the gate is
   passed at 1.0.1 and the rubric's author asked to review per-item verdicts
   before anything is final, so a bump to 1.0.2 is their call rather than a
   unilateral one.

**Padded − degraded = 0.00 exactly.** The padded report is 7,959 characters
(+66%) longer than the degraded one and every one of the 22 items landed on
the same score. That is the anti-length measure working, not a coincidence of
rounding.

# v1.0.2 — the version of record

One change from 1.0.1: **B2's price-claim unit is now mechanical**, so the
denominator stops depending on judgement. Authored by the rubric's designer
after the 1.0.1 re-grade showed the denominator swinging 10–13 on identical
material. Scope is the **report only**; one claim per distinct
*(provider, program/package, dollar figure)* triple; packages per package;
per-session and package prices are separate; a range is one claim; repeats
dedupe; excluded providers count; an aside counts iff it names provider *and*
program; a market rate with no named provider is not a claim.

**Yes.** The B2 denominator is now **11 / 11 / 11** across all three passes on
every axis-B artifact — unanimous, where 1.0.1 gave 13 / 12 / 10. B2 settles
at 4/11 → 2.18. Unanimity rose to 100% on the baseline and both controls; B2

3. Degraded **−19.00** vs baseline; padded − degraded **0.00**.
4. Unanimity **100%** and **94.44%** on the real runs.
5. Human spot-check still **NOT RUN** — deferred to the stage-1a readout.

## One item moved that B2 cannot explain

The Aug-1 run's **A8 went 6 → 0** on a 2–1 split, dropping its A+C from 73 to
67. 1.0.2 touched only B2, so this is not a rubric effect — it is a latent
ambiguity that happened to land pass/pass/pass at 1.0.1 and 1/0/0 here.

The evidence makes the disagreement legible. Two passes failed it quoting the
heading **"## The 8-week plan"**; the pass that succeeded quoted content from
inside weeks 1–4. A8 asks for a plan that "covers exactly weeks 1 through 4",
and the Aug-1 run wrote an **eight**-week plan that contains weeks 1–4 and
then keeps going. Whether that satisfies A8 or fails it turns entirely on how
hard the word "exactly" is read.

Two reasons this is a design question rather than a wording fix:

- **It may be double-counting.** The Aug-1 run already scores **C2 = 0** for
  going beyond the three questions asked. Failing A8 for the same
  over-delivery charges it twice — the kind of double-count the design
  deliberately avoids elsewhere (retrieval redundancy is kept out of the score
  precisely because it is already on the cost axis).
- **Either reading changes intent, not just wording.** "A longer plan that
  contains weeks 1–4 satisfies A8" and "A8 requires the plan to stop at week
  4" are different criteria, and picking one is the designer's call.

Left as-is at 1.0.2. Flagged for the rubric's author.
